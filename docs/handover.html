⚡ 一页总览 · One-page Summary

FluxMind 是一套基于 检索增强生成（RAG） 架构的研究 Copilot，聚焦于 滑模控制（Sliding Mode Control） 与 磁链估计（Flux Linkage Estimation） 两个控制工程子领域。 系统提供论文级问答、数学推导讲解，以及 MATLAB / Simulink 代码生成能力。

技术上做了三件超出"原型"层级的事： ① 推理模型的思考过程流式可视化——用户不再面对黑盒； ② Web UI 与 FastAPI 双形态交付——可作为 Coze 智能体的自定义插件挂载； ③ 双层语料管理 + 手动激活机制——预置语料库与用户上传分离，索引内容可精确控制。

系统已部署上线，通过 Cloudflare Tunnel 暴露公网入口，运行于独立 systemd 服务，与同主机其他业务完全隔离。

核心特性

六个工程层面的关键能力。
01语料驱动的问答
用户上传 PDF 研究论文即自动完成解析、切片、向量化、入库；提问时按语义相似度召回 top-k 块作为上下文， 在回答中标注来源论文与页码，避免大模型自由编造。
回答必须有据可查 —— 这是学术工具区别于通用聊天机器人的根本边界。
02推理过程可视化
底层 LLM 为推理模型（reasoning model），其思考链以折叠引用块实时呈现， 随后以水平线分隔，接入正式答案。用户可观察模型如何拆解问题、组织证据。
学术场景下，"答案如何得出"与"答案本身"同等重要 —— 透明化推理也方便人工二次审校。
03双层语料库
预置语料库（papers/library/，带 manifest 元数据）与 用户上传（papers/uploads/）严格分离； 侧栏多选界面可任意组合启用，精确控制 RAG 索引中的论文集合。
研究场景常需"只在这几篇论文范围内回答" —— 而非把所有材料一锅端。
04MATLAB / Simulink 代码合成
系统提示词默认 MATLAB 语法输出，可一键产出滑模控制器、MRAS 磁链观测器、扩展卡尔曼滤波器（EKF）等 控制工程典型模块的可运行代码骨架。
把"论文读懂"和"工程能跑"之间的鸿沟用代码骨架补齐 —— 这是助手而非问答机器人的关键。
05中英双语界面
UI 侧栏内置中英文切换，所有提示语、按钮、上传反馈、占位符均完成本地化； 系统提示词同时约束模型以用户提问的语言作答。
控制工程文献中英文混杂是常态 —— 切换语言不应是"换一套界面"，而应是无缝的交互。
06开放 API + Coze 插件
除 Web UI 外开放 /query 与 /health 两个 FastAPI 端点，符合 OpenAPI 3 规范， 可直接挂载为 Coze 智能体的自定义工具插件，受 Token 鉴权保护。
让 FluxMind 不止是一个独立应用，而是一个可被其他 Agent 调用的能力 —— 即"可组合中间件"。

工程深度

超出"能跑通"层级、最能体现设计判断的四个决策。

1 · 推理流式输出的 UX 处理

系统选用的 LLM 属于推理模型（reasoning model）——在 OpenAI 兼容协议下，每个 SSE chunk 的 delta 同时具备 content 与 reasoning_content 两个 channel。模型在思考阶段仅填充 reasoning_content， content 字段为空字符串。直接套用 LangChain 默认 chain.stream() 仅消费 content channel， 会导致前端出现 5–15 秒的"静默等待"。系统改为直接调用 OpenAI Python SDK 自管 SSE，并对两个 channel 分别处理： 

# src/chain.py · query_stream（核心片段）
for chunk in stream:
    delta = chunk.choices[0].delta
    reasoning_piece = getattr(delta, "reasoning_content", None)
    content_piece   = getattr(delta, "content", None)
    if reasoning_piece:
        if not reasoning_started: yield "> 💭 "
        yield reasoning_piece.replace("\n", "\n> ")
    if content_piece:
        if reasoning_started and not answer_started:
            yield "\n\n---\n\n"
        yield content_piece

对非推理模型（无 reasoning_content 字段），同一段代码自然降级为纯内容流式输出，无需任何分支判断。

设计意图：透明化模型推理对学术工具尤其重要——用户应能看到"答案是如何被组织出来的"，而非只面对一个黑盒。这是 FluxMind 区别于通用聊天界面的核心 UX 决策。

2 · 双层语料库 + 手动激活机制

研究助手的常见痛点是知识库范围控制——用户往往希望"只在这 5 篇论文范围内回答"，而不是把所有上传过的文献一并参与检索。 为此系统将语料分为两层：

  • papers/library/：仓库内置的精选语料，附带 manifest.json 元数据（标题、主题分类）
  • papers/uploads/：用户运行时上传，已被 gitignore，不污染仓库

侧栏多选界面允许用户任意组合激活论文，点击"应用选择并重建索引"后，系统重建 FAISS 索引并将选择持久化到 faiss_index/active_papers.json。下次启动直接恢复上次激活集。

设计意图：把"知识库"从一个无差别的黑盒解耦为可被显式管理的资源——这是从"原型"走向"准生产"的关键标志。

3 · 上传通道的安全加固

开放上传是 Web 应用最常见的攻击面。系统在 src/ingestion.py 中加入三重防护：

  • 文件名清洗：_safe_pdf_name() 移除路径分隔符与特殊字符，限长 120 字符，防止路径穿越（path traversal）
  • 大小限制：MAX_UPLOAD_SIZE_MB 环境变量配置（默认 50 MB），超限直接拒绝
  • 内容校验：解析后若 PDF 提取不出任何文本（如纯扫描版），直接抛出明确错误，避免污染向量索引
设计意图：暴露在公网的接口必须假设输入是不可信的。这三层防护对应于 OWASP 上传攻击的常见路径。

4 · API 鉴权的双格式兼容

/query 端点同时接受 X-API-Key 自定义头与标准 Authorization: Bearer <token>， 前者适配 Coze 自定义插件的鉴权字段映射，后者兼容 curl / OpenAI SDK 等主流调用方式。 当 FLUXMIND_API_TOKEN 未配置时鉴权跳过，便于本地开发不受打扰。

5 · 多服务隔离部署

主机同时承担其他业务（容器化 QQ 机器人），FluxMind 部署严格遵循以下隔离边界：

  • 独立运行时账户 fluxmind:fluxmind，独立 venv 目录 /opt/fluxmind/venv
  • 独立 systemd 服务两个：UI 服务 :18501、API 服务 :18502，资源软限 CPUQuota=150%, MemoryMax=1400M
  • 独立 Cloudflare Tunnel cloudflared-fluxmind-smy.service，避免与现有隧道命名/端口冲突
  • 不依赖、不修改、不重启同主机 Docker 容器栈，并通过 live-check 验证既有服务在部署前后状态一致

安全性

  • 密钥分层存储：LLM API Key、API Token、Cloudflare Tunnel Token 全部留在服务器 /opt/fluxmind/.env（权限 600），不进入 Git 仓库。
  • 反向代理边界：UI 通过 Cloudflare Tunnel 暴露，源站不开放任何公网端口；API 端口 18502 仅在内网与受信任 Agent 调用，并叠加 Token 鉴权。
  • 最小权限运行时：systemd 服务以非 root 用户运行，NoNewPrivileges=true 阻止提权。
  • 无外发依赖：嵌入模型与向量库完全本地化，论文内容不发送给任何第三方搜索/嵌入服务。
  • 上传防护：文件名清洗 + 大小限制 + 内容校验，覆盖 OWASP 文件上传常见攻击面。

可扩展方向

本次交付为可独立运行的最小闭环，以下方向可作为后续研究 / 毕设迭代点。
  • 多阶段重排（Reranker）：在 FAISS top-k 召回后接入 cross-encoder 二阶段重排，提升复杂技术问题的命中精度。
  • 结构化引用追溯：将回答中的论据片段以可点击锚点链接到 PDF 原文页码，实现可审计的学术问答。
  • 中文语料专项：嵌入模型可热切到 BGE-zh / E5-multilingual，重建索引后即可获得中文论文的高质量召回。
  • Simulink 模板生成：扩展为可直接产出 .slx 模型骨架，对接控制工程教学场景。
  • 多模态扩展：识别论文公式图、Bode 图、相轨迹图，进入向量空间，支持"图问图"。
  • HIL 集成：对生成的控制器代码自动下沉至硬件在环测试台，闭环验证 SMC 抗抖振等指标。
交付边界说明：当前版本聚焦于"知识检索 + 答案生成 + 代码骨架"三件事。上述扩展方向均不在本次交付范围内，但系统架构与代码组织已为其留出清晰扩展点。

常见问题

面向评审与使用者的高频问题集。
这与直接使用 ChatGPT 检索论文有何不同？
三个核心差异。其一，FluxMind 在用户指定的论文集合上做检索，每个回答可追溯到具体论文与页码；其二，检索结果先于生成出现，压缩了模型自由发挥的空间；其三，FluxMind 同时是 UI 与 API，可被其他 Agent 平台（如 Coze）作为工具调用，定位是"可组合的领域能力"而非聊天框。
为什么没有对大模型做 fine-tune？
在控制工程文献的体量与更新节奏下，RAG 比 fine-tune 性价比更高：新增论文无需重训、回答始终基于真实文本而非"模型记忆"、调试时可定位是检索失误还是生成失误。fine-tune 适用于风格/格式定制，不适用于知识更新。
如何应对大模型的"幻觉"？
幻觉无法被根除，只能被约束。系统采取三层防护：检索层提供论据上下文；系统提示词强制要求引用，并在检索内容不足时返回"不知道"而非自由发挥；推理过程可视化让用户能判断模型推理是否站得住脚。下一步将加入 cross-encoder 重排与引用页码锚定，进一步压缩自由发挥空间。
是否支持中文论文？
支持。当前嵌入模型为 MiniLM 英文基线，对中文语义保留略弱；架构上嵌入模型为一行环境变量可替换——切到 BGE-zh 或 E5-multilingual 并重建索引即可获得中文专项能力，代码层无须改动。
系统的性能瓶颈在哪？
三段管线中，检索为毫秒级（FAISS 本地）、嵌入为十毫秒级（MiniLM CPU）、唯一明显延迟在 LLM 推理。对推理模型还需叠加思考链时间，系统通过流式输出 + 思考过程可视化对冲用户感知延迟。
能否完全离线运行？
检索栈完全离线——嵌入、向量库、PDF 解析均在本地。唯一联网项是 LLM 调用。将 LLM_BASE_URL 指向本地部署的 Ollama / vLLM / TGI 即可实现全栈离线，因协议为 OpenAI 兼容，代码无须改动。

关键术语对照

术语简释
RAG · 检索增强生成大模型回答前先从知识库检索相关片段，再以此为依据生成回答，显著降低"幻觉"。
Embedding · 向量化将文本映射到高维向量空间，使语义相近的文本在空间中也相近。
FAISSFacebook AI 开源的向量相似度搜索库，本系统使用其 L2 距离索引，本地常驻。
Reasoning Model · 推理模型在产出最终答案前先输出一段"思考链"的大语言模型，本项目对此做了流式 UX 适配。
SMC · 滑模控制变结构控制方法，通过设计切换函数将系统状态驱动到滑动面，具有强鲁棒性。
MRAS · 模型参考自适应系统通过参考模型与可调模型的输出误差自适应调整参数的观测器结构。
EKF · 扩展卡尔曼滤波对非线性系统进行局部线性化后应用卡尔曼滤波的状态估计算法。
Chattering · 抖振滑模控制中由开关项引发的高频振荡现象，是高阶 SMC / 边界层方法重点研究问题。
OpenAPI 3RESTful API 的标准描述协议，FastAPI 自动生成；Coze 等智能体平台可据此自动识别工具调用方式。
Cloudflare Tunnel从源站主动出站到 Cloudflare 边缘的反向代理通道，源站无需公网 IP 或开放端口。
