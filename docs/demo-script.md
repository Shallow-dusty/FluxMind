## 🎬 五分钟演示流程

### Step 01 · 介绍主界面（约 30 秒）

🎯 **动作**：让评审看到当前这个 Streamlit 主界面。指着左侧栏。

💬 **话术**：
> "左侧是 **知识库管理**。当前预置了 **6 篇精选论文**，覆盖滑模控制与磁链估计两个方向，全部是 CC BY 或 arXiv 开放访问的真实研究文献。每篇论文带 **[Seed] 或 [Upload] 标签**，区分预置语料和用户上传。"

✨ **亮点**：让评审看到这是"真项目"——有真实文献，不是空壳。

---

### Step 02 · 第一问：英文 SMC 比较（约 90 秒）

🎯 **动作**：点击示例问题 *"Explain the reaching law design in sliding mode control"*，或直接在输入框输入。等待回答。

💬 **话术**：
> "您看，答案上方这个 **💭 引用块**就是模型的 **推理过程**——它在思考时如何拆解问题、检索哪些段落、组织哪些证据，全程对用户可见。分隔线下面才是正式回答，并且 **带具体论文和页码引用**。"

✨ **亮点**：流式输出 + 推理可视化 + 带引用。这是项目最容易"出彩"的一步，**请放慢节奏让评审看清楚**。

---

### Step 03 · 第二问：中文双语（约 60 秒）

🎯 **动作**：在输入框里用中文提问，比如：

```
请用两句话解释 PMSM 滑模观测器和扩展卡尔曼滤波器在磁链估计上的取舍。
```

💬 **话术**：
> "系统会 **以提问语言作答**，这不是简单的界面 i18n 切换，而是在模型层面做了语言约束。控制工程文献中英文混杂是常态，所以这点对实际使用很重要。"

✨ **亮点**：中文回答 + 引用文献。如果检索回来的论文是英文、回答是中文，更显出系统的双语融合能力。

---

### Step 04 · 展示语料库管理（约 45 秒）

🎯 **动作**：回到侧栏，**取消勾选**其中 2-3 篇论文，点击 *"应用选择并重建索引"*。等待几秒看到重建完成提示。

💬 **话术**：
> "研究场景常常需要 **限定知识库范围**——比如'只在这几篇论文里回答'。我把激活的论文清单做了持久化（`active_papers.json`），下次启动会自动恢复上次的选择。这把'知识库'从一个无差别黑盒变成了 **可被精确管理的资源**。"

✨ **亮点**：这一步显示出系统的"准生产"层级——不只是能跑，而是考虑过实际研究场景的需求。

---

### Step 05 · （可选）上传演示（约 30 秒）

🎯 **动作**：如果评审感兴趣"能不能上传自己的论文"，可以演示。提前准备一个小 PDF 拖入上传区。

💬 **话术**：
> "上传通道做了 **三重安全防护**：文件名清洗防止路径穿越、大小限制（50 MB 默认）、上传后校验 PDF 是否真有可提取文本以免污染索引。**中文 / 日文 / 俄文文件名都能正确保留**，同名上传会自动加序号避免覆盖。"

✨ **亮点**："安全意识"是工程层级的关键加分项。即使评审不追问，主动提一句"防路径穿越"会让对方觉得你考虑过实际部署场景。

---

### Step 06 · （可选）展示开放 API（约 30 秒）

🎯 **动作**：如果评审是技术背景，可以打开 `http://223.6.253.9:18502/docs`（FastAPI 自动生成的 Swagger 页面），让他看到 `/query` 和 `/health` 两个端点的 OpenAPI 描述。

💬 **话术**：
> "除了 Web UI，系统还开放了 **FastAPI 端点**，符合 OpenAPI 3 规范，可以直接挂载为 **字节跳动 Coze 智能体的自定义工具插件**。这意味着 FluxMind 不只是一个独立应用，而是一个可被其他 Agent 调用的 **领域能力**。"

✨ **亮点**："可组合中间件"是商业 PPT 黑话，但用在这里特别合适——因为 API 确实已经接通 Coze。

---

### Step 07 · 收尾 · 打开架构图（约 45 秒）

🎯 **动作**：打开 `docs/handover.html`，滚到"系统架构"那张 SVG 图。从顶到底过一遍。

💬 **话术**：
> "这是系统架构图。**两层经典 RAG 范式**——上半是检索层，用户问题先做 **向量化**，然后在 FAISS 里做 **语义相似度检索**；下半是生成层，把检索到的论文片段和问题一起喂给大模型生成最终答案。**两层完全解耦**，向量库、嵌入模型、大模型都可以独立替换。"

✨ **亮点**：把"完全解耦"这个词说出来——这是工程判断力的体现。最后用一句 *"基于这套架构，未来可以接入重排器、Simulink 模板生成、或硬件在环验证"* 自然过渡到 Q&A。

## 🛡️ 常见追问 · 兜底答案

> 每个答案 **背 2-3 句话**即可。评审不会让你长篇大论。

**Q · 这和直接用 ChatGPT 检索论文有什么区别？**

> **三个核心差异**。一，ChatGPT 不知道我的私人文献库，FluxMind 是在用户指定的论文集合上做检索，每个回答可 **追溯到具体论文和页码**；二，**检索结果先于生成出现**，压缩了模型自由发挥的空间，降低幻觉；三，FluxMind 同时是 Web UI 和 API，可以被其他 Agent 平台调用，**是工具而不是聊天框**。

---

**Q · 为什么没有对大模型做 fine-tune？**

> 在控制工程文献的体量与更新节奏下，**RAG 比 fine-tune 性价比更高**——新增论文无需重训、回答始终基于真实文本而非"模型记忆"、调试时可以分别定位是检索失误还是生成失误。fine-tune 适合做风格定制，不适合做 **知识更新**。

---

**Q · 模型还是可能产生幻觉，怎么应对？**

> **幻觉无法被根除，只能被约束**。系统做了三层防护：**检索层**提供论据上下文；**系统提示词**强制要求引用，并在检索内容不足时返回"不知道"而非自由发挥；**推理过程对用户可见**，方便人工审校。下一步会接入二阶段重排和引用页码锚定。

---

**Q · 中文论文支持怎么样？**

> 当前嵌入模型是英文基线 MiniLM，对中文语义保留略弱。架构上嵌入模型是 **一行环境变量可替换**——切到 BGE-zh 或 E5-multilingual 重建一次索引就行，代码层无须改动。我把这点留给后续扩展。

---

**Q · 性能瓶颈在哪？**

> 三段管线里，**检索是毫秒级**的（FAISS 本地）、**嵌入是十毫秒级**的（MiniLM CPU）、唯一明显延迟在 **LLM 推理阶段**。对推理模型还要叠加思考链时间，我用流式输出 + 思考过程可视化对冲了用户感知延迟。

---

**Q · 系统能完全离线运行吗？**

> **检索栈完全离线**——嵌入模型本地、FAISS 本地、PDF 解析本地。**唯一联网的是 LLM 调用**。把 `LLM_BASE_URL` 指向一个本地部署的 Ollama 或 vLLM，系统 **不需要改任何代码**，因为协议是 OpenAI 兼容的。

---

**Q · 为什么前端用 Streamlit 不用 React？**

> Streamlit 让我在 **不写一行前端代码** 的前提下做出可交互对话界面、文件上传、流式渲染。这是个研究工具不是 to C 产品，**研发效率优先于视觉打磨**。如果未来要做正式产品，FastAPI 后端保留、前端换成 React 即可——我现在就已经是 **前后端分离的双形态架构**。

---

**Q · 代码量看起来不大？**

> 代码行数不大，**但这是优势不是劣势**。工作量花在三件事：**组件选型**（每个都比较过备选）、**把 LangChain 默认流式行为改造成支持推理模型**的版本、以及 **生产部署**——systemd 双服务、Cloudflare Tunnel、Token 鉴权、与同主机其他业务隔离。**"代码少"恰恰说明组件选对了**。

## 📖 关键术语速查

> 演示前快速过一遍即可——评审随口提到这些词时不会卡住。

| 术语 | 一句话解释 |
|---|---|
| **RAG** | 检索增强生成——大模型回答前先从知识库检索相关片段，以此为依据生成回答，显著降低幻觉。 |
| **Embedding** | 向量化——把文本映射到高维向量空间，语义相近的文本在空间中也相近。 |
| **FAISS** | Facebook AI 开源的向量相似度搜索库（读作 /feɪs/，像 face），本地运行无外部依赖。 |
| **Reasoning Model** | 推理模型——在产出答案前先输出"思考链"的大语言模型，本项目对此做了流式可视化适配。 |
| **FastAPI** | Python 高性能 Web 框架，自动生成 OpenAPI 文档，本项目用来对外开放 `/query` 端点。 |
| **Streamlit** | Python 数据应用框架，无须写前端即可做出交互式 Web 界面。 |
| **Cloudflare Tunnel** | 反向代理通道——源站主动出站到 CF 边缘，无需公网 IP 或开放端口。 |
| **SMC** | 滑模控制——变结构控制方法，通过切换函数把状态驱动到滑动面，强鲁棒性。 |
| **MRAS** | 模型参考自适应系统——通过参考模型与可调模型输出误差自适应调整参数。 |
| **Chattering** | 抖振——滑模控制中由开关项引发的高频振荡，是高阶 SMC 重点研究问题。 |
